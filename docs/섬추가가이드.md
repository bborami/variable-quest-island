# 퀘스트 섬 통합 규칙 (변액 · 생명 · 손해)

한 저장소(bborami/variable-quest-island)에서 상단 세그먼트로 세 섬을 오갑니다.

| 과목 | 폴더 | 주소 | data-subject | localStorage 키 |
|---|---|---|---|---|
| 변액 | `/` (루트) | bborami.github.io/variable-quest-island/ | `variable` | `byeonaek-quest-v1` |
| 생명 | `/life/` | …/variable-quest-island/life/ | `life` | `life-quest-v1` |
| 손해 | `/nonlife/` | …/variable-quest-island/nonlife/ | `nonlife` | `nonlife-quest-v1` |

## 각 섬이 지켜야 할 것
1. 섬 하나 = 자기 폴더 안의 `index.html` 한 파일(필요하면 같은 폴더에 이미지 등). 경로는 모두 상대경로.
2. `<html lang="ko" data-subject="life">` 처럼 과목 id 지정.
3. `<head>`에 `<script src="../shared/segment.js" defer></script>` 추가.
4. 세그먼트를 놓을 자리에 `<div data-quest-seg></div>` (예: 왼쪽 위 제목 카드 바로 아래). 없으면 왼쪽 아래에 떠서 표시됨. 모바일 화면이 따로 있으면 그쪽에도 하나 더 둬도 됨(모든 자리에 그려짐).
5. 진행 기록 localStorage 키는 위 표의 과목별 키만 사용(섬끼리 기록이 섞이지 않게).
6. 공용 아이콘은 `../favicon-32.png`, `../apple-touch-icon.png`를 써도 되고 과목별로 따로 둬도 됨.

## 공유되는 것
- 닉네임·옷 색: `QuestCommon.profile()`로 읽고 `QuestCommon.saveProfile({nick,color})`로 저장 (localStorage `quest-profile`).
- 같이 공부(Firebase): 변액과 같은 config, 같은 경로 `studying/{uid}` 에 `{name, since: serverTimestamp(), color, subject}` 기록, `onDisconnect().remove()`.
  `subject`에 과목 id를 넣으면 다른 섬에서는 이름 앞에 [생명]/[손해]로 표시됨. 독서실은 세 섬이 같은 사람 목록을 봄.
  Firebase 규칙은 바꿀 필요 없음(name 12자 이하, since 필수).
- 첫 화면 디자인: 클레이모피즘(파스텔 보라 #7b5cc7, 분홍, 민트, 둥근 그림자) 톤을 맞추면 전환이 자연스러움.

## 🔒 비밀번호 잠금 (2026-11-17~)
세 섬의 `index.html`은 **암호화된 잠금 페이지**예요. 문제·해설 원문은 공개 저장소에 올리지 않습니다.
- 원본(암호화 전) 파일: 프로젝트 비공개 폴더 `퀘스트섬통합/원본/` 의 `index.html`, `life/index.html`, `nonlife/index.html`
- 수정 순서: 원본을 고친다 → `QUEST_PW='비밀번호' node tools/lock.mjs <원본폴더>` → 바뀐 잠금 페이지 3개를 커밋
- 비밀번호는 저장소에 적지 않아요. 바꾸면 모두 다시 입력해야 하니 같은 비밀번호로 빌드할 것.
- `tools/lock-salt.txt`는 그대로 둘 것(바꾸면 저장된 비밀번호가 풀려 다시 입력해야 함).
- 방식: gzip → AES-256-GCM, 키는 PBKDF2-SHA256(25만 회). 한 번 맞히면 그 브라우저 localStorage `quest-lock-key`에 키를 저장해 세 섬 모두 자동으로 열림.
- 카톡 미리보기용 head 메타(og·아이콘)는 원본의 `segment.js` 줄 앞부분을 그대로 복사해서 잠금 페이지에도 들어가요.
